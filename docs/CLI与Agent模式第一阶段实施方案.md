# CLI 与 Agent 模式第一阶段实施方案

日期：2026-10-28  
状态：首版已实现，待代码审查；实际交付边界与使用方式见文末和《CLI与Agent使用与验证》。  
范围：配置修改、Codex Agent、渐进式 Skill、本地对话入口、通用远程 Channel 和任务回传。

## 1. 已确认的设计约束

1. 本地聊天和 ASR 都可以调用 Agent；继续沿用 AiService → LlmService，不要求本地对话经过插件 Channel。
2. Channel 是远程插件对话入口。AstrBot 是现有插件之一，不是核心固定依赖；后续可以增加其他平台或穿透连接插件。
3. 本地与远程两条路径复用 LLM 的 Skill 加载、工具调用和后端命令能力，但保留独立的对话身份、模型配置、并发策略和呈现方式。
4. Electron 增加 cli module。各业务模块贡献自己的命令，执行成功后发布状态变化；业务与存储职责仍属于原模块。
5. 前端不新增 Agent domain，不新增终端页面。现有聊天界面可增加简洁任务卡；插件按平台能力展示任务消息。
6. Codex 优先通过官方 TypeScript SDK 适配，沿用外部 harness；不自己实现文件检索、代码编辑循环、执行规划或项目上下文管理。
7. Agent 工具采用 Skill 式渐进加载。默认只提供精简能力目录，需要时再加载说明和工具定义。
8. 命令提交需要幂等；任务状态由 Electron 管理，不能被聊天取消、TTS 结束或窗口订阅卸载隐式终止。
9. 普通聊天继续现有记忆策略；Agent 操作只携带必要任务上下文，不归档完整执行日志或项目内容。
10. 用户已授权实现。新增能力通过现有模块装配；穿透、平台协议与平台鉴权属于插件，不在核心实现 TUN。

## 2. 第一阶段交付与范围外事项

### 2.1 必须交付

- 自然语言修改允许暴露的全局配置与模型配置，持久化后同步现有窗口快照。
- 本地聊天、ASR 最终识别文本均可启动、查询、续接和取消 Codex 任务。
- 远程插件通过现有 ConversationChannel 发送自然语言，由宿主通用 LLM 能力处理配置或 Agent 意图。
- Skill 目录、按需加载、结构化工具调用和有限工具循环。
- Codex SDK 适配、工作区选择、任务身份、事件、取消、幂等和最小持久化。
- IPC 推送、通用 HTTP/SSE 适配和薄 CLI 入口，复用同一命令与事件协议。
- 复用现有 AstrBot 插件验证远程闭环，必要时增量映射通用任务事件，不重建专用 AstrBot 后端。
- 与现有气泡、TTS、动作和插件卸载行为的回归验证。

### 2.2 本阶段不做

- Cursor 实现；只预留 provider 适配边界。
- 新建手机聊天网页、终端页面、完整 IDE 或另一套 Agent harness。
- 在 Electron 主进程重新实现无界面 LLM 对话运行时。
- 新的 ASR 高精度复核实现；先复用现有可用的最终文本输入。
- 任意 shell 字符串执行接口、任意配置文件写入或自动暴露全部内部服务。
- 不可信第三方后端插件执行环境、完整插件沙箱和任意 renderer 函数迁移至主进程。
- 自动接管另一台主机上的 Codex；本阶段任务在承载 Electron 的开发机执行。

## 3. 总体调用链与入口归属

```text
本地聊天 / ASR 最终文本
    → AiService → LlmService ───────────────────┐
                                               │
远程平台 / 连接插件                              │
    → 插件 ConversationChannel                  │
    → ConversationScheduler / 对话执行适配器 ────┤
                                               ↓
                               共用 LLM 请求与 Skill / 工具协调能力
                                               ↓
                                    Electron bridge / IPC
                                               ↓
                                          CliService
                                     命令校验、幂等与分发
                                      ↙              ↘
                           所属模块的配置用例       AgentTaskService
                                 ↓                       ↓
                          持久化、发布快照           CodexAdapter / SDK
                                                         ↓
                                                   本机 Codex harness

终端 live2d / 已授权结构化客户端
    → 本机命令接口 → 同一个 CliService

任务与配置事件
    → 本地 IPC / 远程 SSE
    → 本地任务卡或远程 Channel 的任务订阅
    → 远程插件自行映射到平台消息
```

### 3.1 本地与远程不是同一个入口

- 本地桌宠对话保持当前 AiService 的运行权归属；控制面板的输入仍转交现有本地对话消费路径。
- 远程自然语言由插件 Channel 接入，不绕过宿主 LLM、不要求 AstrBot 自己先进行一次 Agent 工具决策。
- 复用的是工具协调实现和后端命令，不是让所有窗口再次监听并执行相同聊天请求。
- 两条路径都可以执行 Agent；远程 Channel 不成为本地 Agent 的前置依赖。
- 结构化命令接口供 CLI、设置 UI 和明确授权的程序调用；它与自然语言 Channel 是两个入口，不能混为一次请求重复执行。

### 3.2 远程连接与 AstrBot 解耦

- 现有 AstrBot 的 WebSocket 协议、设置卡、连接重试与平台消息格式继续留在插件目录。
- 核心只识别宿主分配的来源身份、Channel、会话、发送者与请求，不写 AstrBot 专用分支。
- TUN/隧道解决网络可达性，不替代 Channel、调用身份或权限；其他连接方式使用相同协议即可接入。
- 第一阶段不要求现有 AstrBot 从 WebSocket 改为 SSE。SSE 是新增通用远程客户端的事件适配方式，插件可保留自己的传输。
- 如果通用 HTTP 接口接收自然语言消息，应路由到一个已注册且可用的远程 Channel 执行端，而不是直接转为 agent.run。
- 当前 LLM 执行端位于 renderer：远程 Channel 执行端不可用时明确返回 unavailable。已有 Agent 任务仍由 Electron 运行、查询和取消；不宣称关闭全部 renderer 后仍可新发起自然语言聊天。

## 4. 命令模块设计

### 4.1 组件职责

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| CliService | 命令注册、发现、校验、权限上下文、幂等分发 | 直接操作所有业务存储 |
| 配置命令处理器 | 调用所属模块的更新用例 | 复制一套配置规则 |
| AgentTaskService | 任务状态、会话映射、排队、取消、事件和恢复 | 代码分析和工具执行规划 |
| CodexAdapter | SDK 参数映射、事件归一化、取消、会话续接 | 接受任意模型生成的 shell 参数 |
| IPC / HTTP / CLI 适配器 | 传输、身份、请求响应转换 | 各自实现业务逻辑 |
| 前端 Skill / 工具协调能力 | 渐进加载、模型工具循环、结果回传 | 拥有后端进程生命周期 |

各模块提供注册函数或命令描述，由 Electron 组合根装配。cli 模块不能反向接管模型、配置、插件存储等服务的生命周期。只将需要显式调用的操作命令化，不把 ASR 音频帧、TTS 时钟或全部内部方法注册成命令。

### 4.2 命令描述与请求

命令定义至少包含：名称、用途、输入 schema、结果类型、所需能力、是否修改状态、执行处理器。LLM schema、HTTP 校验与终端参数映射以同一份定义为来源。

示意请求：

```json
{
  "invocationId": "invocation-123",
  "command": "agent.run",
  "args": {
    "provider": "codex",
    "workspaceId": "live2d-project",
    "prompt": "检查并修复构建失败"
  }
}
```

- 调用者身份、来源插件和实际授权由宿主/传输入口绑定，不信任请求中的自报身份。
- 类型检查不能替代运行时校验；来自模型或网络的参数都走 schema。
- 不接受未知字段、任意 executable、shell 拼接片段或任意目录配置覆盖。
- 错误使用稳定 code 和可读 message；区分参数错误、无权限、不可用、版本冲突、执行失败与状态不确定。

### 4.3 第一阶段命令集合

| 命令 | 功能 |
| --- | --- |
| commands.list | 返回当前调用者有权使用的目录；不默认把完整目录灌进 LLM |
| config.get / config.update | 读取脱敏配置、更新声明允许的字段 |
| agent.providers | 查询 Codex 可用性、版本及适配状态 |
| agent.workspaces | 查询本机已配置且可访问的工作区 |
| agent.run | 创建执行任务并立即返回 taskId |
| agent.continue | 使用明确的任务/会话映射继续执行，返回新的执行 taskId |
| agent.get / agent.list | 查询授权范围内的状态与结果 |
| agent.cancel | 显式取消指定任务，重复取消不重复产生副作用 |

CLI 是薄入口，例如 live2d agent run --workspace live2d-project --prompt "修复构建失败"。不增加 shell 运算符、管道、变量替换或脚本解释器；复杂配置可通过结构化 JSON 参数提交。

## 5. 配置修改与广播

### 5.1 支持范围

第一阶段覆盖现有配置模型中可稳定更新的字段：模型选择、思考深度、显示/语音语言、TTS/ASR 的既有设置、已有 Live2D 模型选择，以及新增 Agent provider 与工作区设置。实施时以真实配置类型确定字段列表，不创造已有服务不支持的配置键。

- global 与 model 分开；模型更新必须捕获明确的目标模型身份，不能执行到一半跟随当前模型变化而写错目标。
- 工作区从本机已配置项目中选择；配置目录绑定按授权能力单独处理，不由普通远程聊天任意扩大访问范围。
- API Key、token 等凭据不进入普通 config.get、工具结果、事件和日志。凭据设置保留受限路径。
- 纯 renderer 展示状态仍归对应窗口，不伪装成后端持久化配置。

### 5.2 更新链路

```text
输入校验 + 授权 + 目标身份 + expectedRevision
    → 所属服务更新并持久化
    → 发布配置事件和权威快照
    → 返回 applied 结果及新 revision
```

- 抽取当前 IPC 中的共同更新与广播流程，让控制面板、CLI、工具调用复用。
- 广播每次成功变更一次；接收端只应用快照，不能将快照回流成第二次命令。
- 持久化失败不发布成功快照；通知失败不能伪装成写入未发生，客户端通过重新查询恢复。
- 同一配置资源的版本校验与写入串行完成；版本跨重启不可悄悄复用，可使用持久化版本或 epoch + revision。
- 旧版本更新返回冲突并要求重新读取；不自动覆盖新配置。
- 单次更新限定一个配置聚合，不声称跨多模块的批量修改具有原子事务。
- 返回结果区分“配置已保存”与“外部运行时已就绪”；例如 TTS 配置写入成功不等于预热成功。

## 6. Skill 渐进加载与 LLM 路径复用

### 6.1 默认上下文

默认仅加入简短能力目录：settings（配置修改）、development（本机开发任务），以及固定 loadSkill 入口。能力目录只列该会话实际有权使用的能力。

```text
用户输入
    → 精简意图/能力选择
    → 普通聊天：继续现有角色对话与记忆路径
    → 需要工具：loadSkill
    → 下一次模型请求附加该 Skill 的说明和工具 schema
    → 完整工具参数校验后执行
    → 将结构化结果交回模型，继续下一轮判断与工具调用
    → 模型明确结束或达到预算上限后，产生简短用户回复
```

- 模型明确选择工具能力后才加载，不靠普通文本中的命令字符串触发执行。
- Skill 是说明与工具集合引用，加载成功不表示已经执行命令，也不扩大授权。
- 设置工具调用轮数、超时和结果大小上限；达到限制后明确结束本轮，不让模型无限循环。
- 不支持原生工具调用的模型返回能力不可用，不退化为执行自由文本命令。
- 流式工具参数完整前不得启动任务；工具调用 delta 与 speak_text/display_text 分开处理。

### 6.2 本地与远程复用方式

现有本地 LlmService 与插件 createDefaultConversationExecutor 是两条执行路径。只改 LlmService 不会自动赋予插件工具能力。

实施时在现有 llm 模块内提取可复用的请求级协调函数：Skill 选择、工具循环、命令调用和输出约束。由本地 LlmService 和远程对话执行适配器共同调用，不新建一个前端 Agent domain，也不让插件通过导入内部服务获得能力。

- 本地仍由 AiService 协调语音、动作和气泡。
- 远程保持 Channel 的场景说明、模型设置、语言和交互策略，不强行使用本地桌宠对话实例。
- 插件只使用公开 host.ai Channel 契约；新增公开方法同步更新类型、权限、Proxy 方法白名单和清理策略。
- Skill 加载状态按会话隔离，完成、空闲或切换能力时收回无关工具定义。
- 一次工具循环中固定能力集合，避免参数尚未提交时 schema 被切换。

### 6.3 记忆与 token 预算

- 工具路径在重型记忆召回之前确定，只携带当前明确指令、必要短上下文和任务引用。
- 普通聊天沿用现有角色记忆；不要为了省 Agent token 全局关闭记忆。
- Agent 代码、日志、diff 和完整执行记录不注入角色长期记忆；如需留痕，仅保存最小用户目标与结果摘要。
- LLM 不通过反复轮询工具获取每条进度；进度由后端事件直达 UI/插件。
- taskId、外部 sessionId 和消息投递关系存为技术状态，不视为角色记忆。
- 旧工具结果在后续轮次中摘要化；只移除工具定义却保留全部历史结果不能达到预算目标。

## 7. Codex 适配与任务管理

### 7.1 SDK 策略

计划优先采用 @openai/codex-sdk。具体安装版本、支持的线程/流式事件/取消接口及其本机运行时依赖，在实施第一步以官方文档、安装类型和本机行为核验后锁定。

- 不承诺一个独立 WASM 参数校验层；SDK 类型不代替外部输入 schema。
- 使用明确的 providerSessionId 续接，不通过 --last 推测会话。
- 不预先编造 SDK 方法；适配器将验证后的事件映射为稳定的内部任务事件。
- 若 SDK 取消无法确认底层进程退出，先补足适配器的进程归属与停止能力，再验收取消；不能仅停止读取事件就标记任务取消。
- 执行策略由本机配置约束；登录失效、权限不足、版本不兼容都明确返回，不静默降级至更大权限。
- 如果需要交互批准，必须显式呈现待处理状态或以具体原因结束；不能无限挂起，也不擅自自动批准。

### 7.2 身份与状态

- taskId：一次执行的唯一 ID；每次 continue 产生新的 taskId。
- providerSessionId：Codex 的持续会话身份，多个顺序执行可共用。
- origin：本地或远程入口，以及宿主绑定的会话与调用者；用于结果路由和访问校验。
- invocationId：请求幂等键；不能与长期会话 ID 混用。

```text
queued → running → succeeded / failed
   ↘ cancelled   ↘ cancelling → cancelled
                 ↘ interrupted
```

必要时增加 waiting-input，但只有实际完成输入回传协议才对外宣称支持；初期非交互限制必须明确。

- 一个工作区同时只执行一个修改任务；排队有上限，可查询和取消。
- 同一 Codex 会话不能并行续接。
- 新聊天、Channel interrupt、TTS 取消、气泡清空、关闭面板都不自动取消已接受任务。
- Channel.cancel 取消当前对话生成；只有 agent.cancel 明确取消后端任务。
- 任务接受后，其 AbortController 不再与原聊天请求或 SSE 连接共用。
- 任务完成与取消竞争时，以实际终态为准，状态只能收敛一次。
- 若整个应用退出，受控停止进程或标记中断；不能因窗口关闭自动声称后台任务已经完成。

## 8. 幂等、存储与回收

### 8.1 去重协议

以可信调用者作用域 + invocationId 为键，同时保存规范化参数摘要。

- 相同键、相同参数：返回原结果/原 taskId。
- 相同键、不同参数：返回 conflict。
- 生成新的 invocationId 表示新的明确操作，不能按相同 prompt 或相同工作区去重。
- 本地重试、插件消息重投与 HTTP 重试沿用同一 invocationId；一次对话多次工具调用分别拥有稳定操作编号。
- 对远程消息在 Channel 接收层也去重，避免重跑一次 LLM 后生成一批新的工具调用 ID。
- 同一进程内“检查并保留调用记录”不可被异步并发穿透；先预留，再启动执行。
- 重复终态、重复取消和重复投递不重复触发业务副作用。

### 8.2 存储建议

| 数据 | 位置 | 回收策略 |
| --- | --- | --- |
| 活跃 SDK 对象、取消控制器、订阅连接 | 内存 | 终态或断开后释放 |
| 调用记录、任务状态、外部会话 ID、结果路由 | 本机轻量持久化 | 终态后按策略回收 |
| 近期任务事件 | 有限缓存/短期日志 | 按数量和体积截断 |
| 完整开发上下文 | Codex | 沿用 harness 自身管理 |

初始建议：终态去重记录保留 24 小时，任务摘要与会话映射保留 7 天；两者均可配置，活跃任务不按终态 TTL 清除。保留期过后拒绝将过期重试静默当成新操作，客户端应显式建立新的请求；协议携带请求有效期以支持这一判断。

首版采用固定的 24 小时调用保留期、7 天任务保留期。调用方必须在重试时保留原 issuedAt，过期信封会被拒绝；不能声称在删除所有去重记录后仍永久识别被重新签发时间的旧 ID。远程对话去重的有效保证范围同样是保留窗口。

持久化复用项目既有基础设施，优先考虑本地 SQLite 的唯一约束和事务；不引入消息队列服务器。配置存储与任务账本跨存储时不假设天然原子性。

### 8.3 崩溃边界

- 在启动外部执行前写入调用保留记录，获得会话标识后及时更新。
- 如果在“外部任务已经启动”和“本地关联落盘”之间崩溃，恢复时标记待核对/中断，不自动重跑。
- 不保证外部文件修改跨崩溃恰好执行一次；保证能够识别已知重复请求，并避免盲目重放不确定操作。
- 配置提交与账本记录之间出现崩溃时，结合版本和当前状态核对；无法确认则返回不确定状态，不能伪报未执行。
- 重启恢复清理过期记录、核对未终态任务，但不会自动续跑用户未重新授权的中断工作。

## 9. 事件、Channel 与远程传输

### 9.1 统一任务事件

建议事件字段：taskId、sequence、type、timestamp、必要 payload。类型至少包括 accepted、started、progress、completed、failed、cancelled、interrupted。

- 终态与结果摘要持久化；连接存活不能替代任务状态。
- 本地用 IPC 推送，HTTP 客户端可用 SSE；后端任务不依赖订阅者数量。
- 定时探针仅做连接/受控执行状态核对，不因一段时间没有模型输出直接判失败。
- 高频进度合并与截断，不把全部 stderr 或包含凭据的原始消息转发给远程模型。
- 进程退出、SDK 终态和异常退出需要相互核对，异常断流不能等同成功。

### 9.2 Channel 契约的增量扩展

保持 sendText / onResponse 的现有聊天语义。接收 Agent 命令后，本轮聊天可以返回“任务已接收”并 done；Agent 仍可继续执行。

为远程 Channel 增加独立的任务观察契约（具体名称在实现时确定），提供任务引用、订阅和快照恢复；不要把多分钟任务伪装成一条永远 streaming 的聊天回复，也不要在 done 之后偷偷复用同一回复流发任务事件。

- 插件按平台能力把事件映射为消息编辑或少量新消息。
- 每条远程结果按可信来源会话路由；其他 Channel/用户不能只凭 taskId 查询或取消任务。
- renderer Channel ID 可变化，持久化关联使用稳定的来源会话身份；重连后重新授权并恢复订阅。
- 插件 dispose 撤销注册与监听，禁止继续调用已失效代理，但不自动删除或停止 Electron 已接受的任务。
- 不承诺外部平台消息严格恰好投递一次；利用事件序号、已确认投递位置和可用的平台幂等键降低重复，断线期间结果仍可查询。
- “Agent 已完成”“宿主已生成通知”“平台已成功投递”分开记录，不混成一个完成标记。

### 9.3 HTTP/SSE 和 CLI

建议最小接口：POST /commands、GET /tasks/:taskId、GET /events。若提供自然语言接口，则经宿主 Channel 适配，不直接猜测为结构化命令。

- 服务默认监听本机；远程接入由已有网络/隧道或插件承担，并绑定独立凭据和调用范围。
- 任务查询、命令和 SSE 使用同一授权边界，不能仅对提交接口做限制。
- SSE 带可恢复的事件游标，断线后补近期事件；游标过期返回快照与新游标。
- 订阅建立与快照读取需避免中间漏事件：采用游标回放或先订阅再补齐，并按序号去重。
- 远程断线不取消任务；不支持推送的连接可使用低频状态查询作为补偿。
- CLI 连接当前 Electron 命令入口，不另开一份配置服务修改相同文件；应用未运行时明确返回不可用。

## 10. 插件扩展边界

- 现有插件系统已有 CommandContribution；沿用其命名和所有权，不创建无法互通的另一套插件命令目录。
- 对需要供 LLM/CLI 调用的贡献补充 schema、说明、执行位置和权限信息，不能自动公开所有 execute(...args) 函数。
- renderer 命令仍在所属窗口执行；注册归属需要包含窗口实例，窗口退出后不可用，不能广播到所有窗口执行。
- Electron 内置模块的命令可不依赖 renderer；任意插件后端入口加载属于后续独立范围。
- 当前 renderer 插件是应用信任代码，公开 API/Proxy 白名单不是不可信代码沙箱，不以此夸大隔离保证。
- 第一阶段新增通用能力并验证已有 AstrBot 接入，不建立 AstrBot 专属 host、任务服务或配置存储。

## 12. 实施阶段与验收

### 阶段一：协议与适配验证

- 确定命令/任务/Channel 扩展类型、权限、幂等和错误协议。
- 核验并锁定 Codex SDK/运行时，验证流式结果、会话续接、停止与退出行为。
- 对现有配置字段与插件执行归属做一次定向梳理。

验收：SDK 能力与方案一致；不支持的交互行为明确返回；不依赖猜测参数。

### 阶段二：配置命令

- 实现 CliService 最小分发与运行时校验。
- 接入配置模块，统一持久化、revision 和快照广播。
- IPC 与现有控制面板复用共同用例。

验收：修改后各窗口一致；失败不假报成功；重复提交不重复写入/广播；版本冲突不覆盖。

### 阶段三：Agent 生命周期

- 实现 CodexAdapter、任务服务、持久化去重、队列和事件。
- 覆盖启动、查询、续接、取消、进程失败、恢复和资源回收。

验收：同工作区串行；同会话不并发；取消不会残留受控执行；异常退出不挂死；重启不盲目重跑。

### 阶段四：本地与远程 LLM 能力

- 实现渐进 Skill 和结构化工具调用。
- 本地 AiService/LlmService 与远程 Channel 执行适配器复用协调能力。
- 接入最小任务卡与 Channel 任务事件；Agent 路径避免完整角色记忆。

验收：本地文字、本地 ASR、远程 Channel 均可操作；普通聊天无完整工具链负担；新聊天/TTS 结束不停止任务；既有插件模型/语言策略保持有效。

### 阶段五：远程与 CLI 闭环

- 接入通用 HTTP/SSE 与薄 CLI，验证鉴权与重连。
- 使用现有 AstrBot 插件完成远程验收，不改变其核心依赖方向。
- 增加第二个模拟远程 Channel，验证能力不依赖 AstrBot 名称或协议。

验收：消息重投不双执行；结果路由正确；断线可恢复；无权限不能查询他人任务；平台消息失败不抹掉已完成结果。

## 13. 测试策略与完成标准

测试按行为边界组织，优先扩展已有测试，不按文件一对一创建。

1. 配置：类型与字段边界、敏感字段、明确模型目标、持久化失败、版本竞争、广播与回流。
2. 幂等：并发重复请求、同键不同参、请求有效期、进程崩溃窗口、记录回收。
3. Agent：结构化事件分片、异常输出、失败退出、续接 ID、工作区排队、取消竞争和资源释放。
4. Skill：渐进加载、按会话隔离、权限不提升、工具参数完整后才执行、工具循环上限、记忆分流。
5. 入口：本地和远程分别发起任务；控制面板不成为第二个本地聊天消费者；远程重投和多窗口不造成重复命令。
6. 生命周期：Channel.cancel/dispose、聊天打断、停止语音、窗口关闭只清理所属订阅；显式 agent.cancel 才终止任务。
7. 传输：SSE 游标恢复、快照切换不漏事件、事件去重、授权、原会话回传、平台投递失败。
8. 回归：普通聊天、动作表生成、TTS、气泡和既有插件文本响应不受工具执行结果污染。

真实 Codex smoke test 仅在明确测试工作区执行；其余流程用可控适配器验证，避免测试意外改动用户项目。

完成标准：第一阶段核心入口都能完成配置修改和 Codex 任务闭环；不会因多窗口、重试或断线重复启动任务；不会因前端对话生命周期变化丢失后端任务；不把 AstrBot 固化进核心架构。

## 14. 本次审查后的默认决策

- 本地入口是 AiService，远程插件入口是 Channel，二者共享 LLM 工具实现。
- cli module 提供统一应用命令，业务模块保留规则、存储和状态权威。
- Codex 使用 SDK 适配；版本与取消能力在编码前验证。
- 内存保存活跃对象，硬盘保存最小幂等/任务记录，并设置回收上限。
- 远程可使用 IPC 之外的 HTTP/SSE，但不强制现有插件替换其 WebSocket 协议。
- 先交付配置修改和 Codex；Cursor、任意后端插件、额外 UI 和独立无界面 LLM 服务后续另行设计。

## 15. 首版落地差异与审查边界

- LLM 工具循环已实现，最多 8 轮、每轮最多 4 次调用，具备整体时间预算和上下文大小上限。普通聊天回到原记忆路径；已处理的工具路径不保存完整 Agent 记录。
- Codex SDK 锁定 0.165.0。SDK 在受 Electron 管理的子进程中运行，取消通过进程树终止，并等待退出确认；SDK 不打包进 renderer。
- 首版账本使用单进程写入的原子 JSON 文件，未引入 SQLite 或外部消息队列。活动任务在内存，调用与任务摘要持久化。
- 配置更新使用当前内容指纹作为 revision，保护读取后被其他变更覆盖的场景；它不是永远递增的历史版本，A→B→A 后内容相同会得到相同指纹。
- 首版开放 schema 中明确声明的全局、字幕、按键、ASR、TTS、气泡与已有 Live2D 模型选择。当前聊天模型和思考深度仍由原前端选择缓存管理，未伪造后端配置字段或迁移其存储归属。
- 任务列表最多返回最近 100 项；前端展示最近 20 项，完整保留期内可按 taskId 查询。
- SSE 每次连接先返回完整当前任务快照，再发后续事件；按任务 sequence 合并。首版不回放所有中间日志，也不承诺平台消息恰好投递一次。
- 远程自然语言继续经插件 Channel。通用 HTTP/CLI 是本机授权的结构化调用入口；不额外实现一个绕过 Channel 的远程聊天路由。
- 现有 AstrBot 增加独立 agent.task 事件，不复用已 done 的 ai.response。外部桥接端需识别该事件才能主动展示任务进度；其原有自然语言请求无需改成工具请求。
- 现有插件命令仍在原 renderer 注册体系中；任意插件自定义命令跨进程代理和动态后端执行器没有在本阶段自动开放。
